## `pratibimb-architect` — L1

**Status: `CONDITIONAL_PASS`.**

### Boundaries

**PASS.** The experiment is entirely T1. No privacy vault, no GLiNER, no visual PII, no
sanitized handoff, no server, no executor. `packages/perception` gained no import of
`tools/`, and `trainingBoundary.test.ts` still passes.

The taxonomy is used correctly throughout: **T1** is UI perception, **T2** the privacy
vault, **D3** GLiNER semantic NER, **D4** visual PII. Nothing in this workstream is called
D3 or D4, and the detector under test is named as what it is.

### Does this belong in `artifacts/experiments/`?

**PASS.** It is a measurement of external behaviour with a verdict, which is what
`experiments/` holds (S-01 through S-05). The harness is throwaway and is gitignored except
its source. The evidence that is kept — `metrics.json`, `reference-summary.json`, `logs/` —
is not generated by the harness build.

### The one architectural concern

**The shipped `PROVISIONAL_THRESHOLDS.score` is 0.25 while QG-05 evaluated at 0.05.** Two
code paths read the same weights and behave differently, and neither number came from the
other. This predates the PR; it is now **visible in one table** in
`docs/testing/threshold-selection.md` §5.2 rather than split across two files. **Not fixed
here** — fixing it means choosing an operating point, and the frozen rule deliberately has
not been applied to a held-out split yet.

### Registry discipline

**PASS.** `feasibility-matrix.md` is edited — that is the point of the work.
`model-registry.md` is **not**. The decision record states both, and the diff shows both.

> Noted approvingly: the decision explicitly says *"this project has twice had a decision.md
> assert a registry effect that was never made"*. The claim in this PR is checkable against
> the diff.

## `ml-engineer` — L2, blocking on model adoption

**Status: `CONDITIONAL_PASS`. The detector is NOT adopted.**

### Correctness methodology

**PASS, and this is the strongest part.** The criterion was pre-registered before any
browser launched, derived from the model's own arithmetic — `exp()` amplification on the box
channels, fp32 SIMD noise on the sigmoid channels — rather than from an observed run.
Measured worst case is ~100× inside it. **The tolerance was not widened at any point**, and
there was no occasion to want to.

Box and class channels are compared **separately**. A single max-abs over the whole tensor
would have been the box error wearing a label claiming to cover both.

### The eval-mode guard

**PASS.** The defect that produced a bogus 40.4 export discrepancy cannot silently recur:
the reference generator **reads** `.training` on every `named_module()` before and after,
the fact is recorded in a committed file, and `qg03Reference.test.ts` fails if either the
assertion or the record is removed. **Three negative controls were run and all three fired.**

A comment would not have caught the original defect — `eval()` *was* called, and something
set the flag back. Reading rather than setting is the right shape.

### Threshold methodology

**PASS on diagnosis and on discipline.**

The old rule is not described as "too lax", which would have been the easy and wrong reading.
It is identified as a **category error**: mAP@0.5 is a ranking metric and is near-invariant
to the emit threshold, so maximising it cannot express a preference between operating points.
The evidence is quantitative — **0.0004 of mAP against 0.1430 of grounding across the same
plateau** — and it is checked by a test that fails if the ratio ever stops holding.

The replacement introduces **no new metric and no arbitrary constant**. The obvious
alternative ("maximise recall subject to grounding ≥ X") was rejected for the stated reason
that X would have no evidence behind it — that is the right call.

**The flatness of the optimum is disclosed.** F1 is within 0.01 at 0.55, 0.60 and 0.65 on 40
dev screens, and the document says so rather than quoting 0.55 as if it were determined.

### The rule was NOT applied to test

**PASS, and this is the correct restraint.** The test split has been read once. A second
look under a new rule would produce a figure indistinguishable in the report from a first
look. The rule is frozen; the evaluation needs an unread split. `thresholdRule.test.ts`
asserts `appliedToTest === false`, and asserts on the analysis **source** that it never
indexes the test predictions — not merely on a self-reported flag.

### Capacity

**PASS.** The brief asked whether the dominant problem is threshold/postprocessing or
capacity. The dev taxonomy answers it: **70% of false positives at the incumbent threshold
overlap nothing at all**, and class confusion collapses 2,543 → 56 when the threshold moves.
Checkbox and radio recall is ~0.9 at 0.05 and ~0.46 at 0.55 with **precision 1.000** — the
model finds small controls and ranks them low, which is calibration, not capacity.

**No capacity increase is recommended, and none was made.**

### Blocking finding

**The model does not survive browser preprocessing.** 16–34% of detections lost. Trained
with `augmentation: "none"` on one resampler. This is an ML problem with an ML fix, it is
recorded as **QG-03a**, and it is **not** fixed here because fixing it means retraining and
re-freezing the regression baseline.

## `browser-engineer` — L2

**Status: `PASS` on method; the matrix verdict is `CONDITIONAL`.**

### ORT integration

**PASS.** The session is created through **ADR-0001's own path** — the shipped
`@pratibimb/security`, not a harness copy — so a change that broke the pin would break this
harness too. That is the correct coupling. The pin installed in all 8 cells.

`ort.all.min.js`, `numThreads = 1`, matching S-03. The CSP is produced by the **shipped**
`buildExtensionPagesCsp()`, so the harness cannot run under a policy the product would
reject, and `connect-src` is pinned to the loopback collector.

### Backend identity

**PASS, and this is the part a weaker harness would have got wrong.** `GPUQueue.submit` is
wrapped **before ORT loads** and counted during inference. A WebGPU cell cannot reach ACCEPT
without observed submissions — asserted in `qg03Matrix.test.ts`, not merely intended.
Fifteen submissions and fifteen compute pipelines observed on both WebGPU browsers.

Adapter identity is recorded from what the browser **returned**: Chromium reports
`intel / gen-12lp`, so every Chromium WebGPU figure is an integrated-GPU figure and the RTX
5050 is unmeasured. Firefox reports an **empty** `adapterInfo` — `identified: false`,
measured rather than assumed from S-02.

### Cross-browser discipline

**PASS.** Eight rows, never merged. Firefox headful and headless are separate because they
**disagree**, and the Firefox WASM (Linux) column is left `UNKNOWN` with an explicit note
that Firefox WASM on *Windows* was measured and is a different cell. That is exactly the
distinction the brief demanded and the easiest one to fumble.

### Preprocessing

**PASS on method, and it found the headline result.** Testing the browser's own letterboxing
was not in the original plan and is the most valuable measurement here. Four variants were
tried, including the browser's own `imageSmoothingQuality: "high"` — reporting "canvas
cannot match PIL" without trying the browser's better option would have been an unfair
comparison.

The finding that **Firefox ignores `imageSmoothingQuality`** (bit-identical low and high) is
a concrete cross-browser behavioural difference, not an inference.

### Harness defects

**Three found, all disclosed, all fixed with verified guards.** Defect 3 is the serious one:
a cell labelled `webgpu` throughout its own log had actually measured WASM. It was caught
only because the probe reports the backend it ran from a different code path than the runner
that labels the file, and the two are now **compared, with the aggregator refusing to emit a
mismatch**. The refusal was demonstrated against the real contaminated data before the
re-run.

Every cell was **re-measured from a clean machine** after the process-leak fix. Discarding
contaminated latency data rather than reporting it is the right call.

## `performance-engineer` — L2

**Status: `PASS` on method.**

### Reporting shape

**PASS against benchmark contract Rule 1.** Session creation, first inference and warm
inference are three separate figures; p50 and p95 are both reported, and p95 is
**suppressed with a stated reason** when fewer than 20 samples support it rather than
printed as a single observation wearing a percentile's name.

### Memory

**PASS against Rule 3 and the project's own methodology.** `WebAssembly.Memory`'s
constructor and `grow()` are wrapped before ORT allocates, so heap size is **read** rather
than inferred. Model file size, WASM linear memory and JS heap are three separate rows and a
committed `caution` field says so — enforced by a test that fails if the caution is dropped.

**`performance.memory` is absent in Firefox and is recorded as `null`, not `0`.** An absent
measurement is not a measurement of zero.

### The findings

- **The 0.30 MB model accounts for essentially none of the 26.4 MB arena.** Quoting the file
  size as a memory figure would be out by ~90×.
- **WebGPU costs 10.4 MB less WASM heap** — Rule 6 mitigation 1, now observed.
- **`release()` returned nothing in any cell.** Consistent with S-04. Fine at one model;
  this is the number that matters at four.
- **Latency is not this model's constraint** — 3–5× inside budget on 3 of 4 backends.

### Concerns

- **Firefox WebGPU at 100 ms is 2.9× over the WebGPU budget** and slower than its own WASM.
  Recorded as QG-03c, unexplained.
- **Chromium WASM headful p95 is 107.5 ms against a p50 of 41 ms** — a long tail that
  headless does not show (30.1 ms p95). Compositor contention is the likely cause; it is not
  investigated and is not claimed to be.
- **No premature optimisation was attempted**, correctly. The brief said characterise.

### On the network evidence specifically

The claim "no runtime model download" is made from an **arrival log**, not from
configuration — `fetch`, XHR, `WebSocket`, `EventSource` and `importScripts` all wrapped,
every URL recorded with its origin classified. `qg03Matrix.test.ts` asserts that the only
permitted arrival pattern is the pinned artifact, so a future cell that fetched anything
else would fail CI rather than pass unnoticed.

This is the discipline S-02a-2a-4 established, applied without being asked to.

## `evaluation-qa-engineer` — L2

**Status: `PASS`.**

### Guards that were proven to fire

**PASS.** Three negative controls on the eval-mode guard (delete the after-assertion, weaken
to a root-only check, falsify the committed record) — **all three failed the suite**, and the
file was restored and re-verified green. The mislabel cross-check was demonstrated against
the real contaminated log before the clean re-run.

A guard that has never fired is not evidence, and this PR does not ask anyone to take one on
trust.

### Test coverage against the brief's list

artifact hash ✅ · model input/output schema ✅ · eval-mode reference ✅ · ONNX-vs-Python
correctness ✅ · deterministic inference ✅ · backend identity ✅ · coordinate mapping ✅ ·
letterbox removal ✅ · frame identity ✅ · malformed output ✅ *(pre-existing in
`uiDetectorHead.test.ts`)* · browser-specific failures ✅ *(Firefox WebGPU headless is a
recorded REJECT cell)* · session lifecycle ✅ · latency benchmark validity ✅ *(p95
suppression rule)* · memory measurement validity ✅ *(three-quantity separation enforced)*.

**405 tests pass.** `typecheck`, `lint` (tsc strict) and `verify-repo` all clean.

### Evaluation defects surfaced

**Credit for finding these rather than reporting around them:**

1. **Recall ceiling 94.4%, not 100%.** 42 of 51 CLIPPED dev annotations are *arithmetically
   unreachable* at IoU 0.5 because they are scored against a full CSS box that is partly
   outside the frame. Found by asking why the clipped bucket barely moved with the threshold
   when every other breakdown moved a lot — **a model failure would have moved**.
2. **The `CLIPPED` label exists in the dataset and the evaluator ignores it**, excluding only
   `OFFSCREEN`.

Both are **deferred, not fixed**, with the correct reason: changing them changes the metric
definition, and that must not happen while a held-out figure is being interpreted.

### One methodological shortfall, self-reported

**Only the correctness criterion was pre-registered.** Latency, memory, backend ranking and
the preprocessing-parity measurement had no prior. The README says so plainly and states the
consequence — those results confirm or refute nothing — rather than retrofitting a
hypothesis. **That is the right disclosure, and it is also a real gap**: S-04a-1 pre-registered
four hypotheses and this experiment pre-registered one. The next experiment should do better.
